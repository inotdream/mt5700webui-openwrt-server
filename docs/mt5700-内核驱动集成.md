# MT5700M-CN 内核驱动集成（固件编译侧）

这份笔记对应厂商文档《MT5700M-CN 5G 系列模组 Linux 内核驱动集成指导》
V200R001C20，只保留在 OpenWrt 上实际需要做的部分，并标出原文档里几处
照抄会出错的地方。

本仓库的 `at-webserver` 只负责在**驱动已经就绪之后**收发 AT 命令。
如果 `/dev/ttyUSB*` 根本没出来，问题在内核配置，不在这个服务。

## 设备标识与端口映射

```
VID:PID = 3466:3301
```

| 设备节点 | 用途 |
|---|---|
| `/dev/ttyUSB0` | Application Interface |
| `/dev/ttyUSB1` | **PCUI — AT 命令口** |
| `/dev/ttyUSB2` | SerialB |
| `/dev/ttyUSB3` | SerialC |
| `/dev/ttyUSB4` | GPS（只吐 NMEA，不响应 AT） |

AT 命令要走 **PCUI，也就是 ttyUSB1**。本仓库的 `serial_port` 默认值就是它。
厂商文档 10.1 节的拨号示例用的也是 ttyUSB1（`echo -e "ate1\r\n" > /dev/ttyUSB1`）。

端口编号不保证稳定。要确认实际对应关系，看
`/sys/bus/usb/drivers/usbserial-generic/*/interface`，或者干脆把
`serial_port` 设成 `auto`，服务会逐个发 AT 找出能应答的端口（优先试 ttyUSB1）。

## OpenWrt 需要的内核模块

厂商文档给的是 `CONFIG_*`，在 OpenWrt 里对应这些包：

| 功能 | CONFIG | OpenWrt 包 |
|---|---|---|
| USB 串口框架 | `CONFIG_USB_SERIAL` | `kmod-usb-serial` |
| option 驱动（推荐） | `CONFIG_USB_SERIAL_OPTION` | `kmod-usb-serial-option` |
| WWAN 支持 | `CONFIG_USB_SERIAL_WWAN` | `kmod-usb-serial-wwan` |
| CDC ECM 网卡 | `CONFIG_USB_NET_CDCETHER` | `kmod-usb-net-cdc-ether` |
| CDC NCM 网卡 | `CONFIG_USB_NET_CDC_NCM` | `kmod-usb-net-cdc-ncm` |
| RNDIS 网卡 | `CONFIG_USB_NET_RNDIS_HOST` | `kmod-usb-net-rndis` |

ECM / NCM / RNDIS 都是标准通用驱动，不需要改内核代码，装上包即可。
只有 USB 串口需要额外让驱动认识这个模组。

`CONFIG_USB_CONFIGFS_*` 那几项是给**做 USB device 端**（把单板自己变成 gadget）
用的，路由器作为 host 接模组的场景不需要，厂商文档里那句「适用于 arm 架构的 PC」
容易让人误加。

## 让 option 驱动认识这个模组

推荐做法，改 `drivers/usb/serial/option.c`。在 `/* Vendor and product IDs */`
之后加：

```c
#define TDTECH_VENDOR_ID			0x3466
```

在 `static const struct usb_device_id option_ids[]` 里加：

```c
{ USB_VENDOR_AND_INTERFACE_INFO(TDTECH_VENDOR_ID, 0xff, 0x06, 0x10) },
{ USB_VENDOR_AND_INTERFACE_INFO(TDTECH_VENDOR_ID, 0xff, 0x06, 0x12) },
{ USB_VENDOR_AND_INTERFACE_INFO(TDTECH_VENDOR_ID, 0xff, 0x06, 0x13) },
{ USB_VENDOR_AND_INTERFACE_INFO(TDTECH_VENDOR_ID, 0xff, 0x06, 0x14) },
{ USB_VENDOR_AND_INTERFACE_INFO(TDTECH_VENDOR_ID, 0xff, 0x06, 0x1B) },
{ USB_VENDOR_AND_INTERFACE_INFO(TDTECH_VENDOR_ID, 0xff, 0x06, 0x1C) },
```

**关键点是按接口描述符匹配（class 0xff / subclass 0x06 / 各 protocol），
而不是按 VID/PID 匹配。** 这样驱动只认领这六个串口接口，不会去碰
ECM/NCM 的网卡接口。

在 OpenWrt 里作为 target 的内核补丁放到
`target/linux/<target>/patches-<ver>/` 下，或者用
`package/kernel/linux/modules/usb.mk` 之外的 quilt 流程管理。

## 关于运行时 new_id（本仓库 init.d 里那段）

`/etc/init.d/at-webserver` 里有一段兜底逻辑，往
`/sys/bus/usb-serial/drivers/<drv>/new_id` 写 `3466 3301`，对应厂商文档
11.5 节的手动加载方法。

这只是给「内核没打上面那个补丁」的情况救急，**只在 `connection_type=SERIAL`
时才执行**。原因是：new_id 是按 VID/PID 匹配的，串口驱动会尝试认领该设备的
**所有**接口，其中 ECM/NCM 的数据接口带 bulk 端点，有被串口驱动抢走的可能，
结果就是 WAN 网卡消失。网络模式下压根不需要 ttyUSB，没有理由承担这个风险。

厂商文档 5.3.3 节那个「跳过 ADB 接口」的补丁，存在的原因正是 usbserial 的
generic 驱动会误认网卡和 ADB 接口。那是内核源码改动，从用户态写 new_id
是绕不过去的——所以生产环境请走上面的 option.c 补丁，别依赖 new_id。

## 原文档里几处照抄会出错的地方

如果你要按厂商文档 5.3 节走 `usbserial.ko` 那条路，注意：

1. **5.3.4 的宏名拼错了。** 文件头部的条件编译写的是
   `CONFIG_SUPPORT_TDTECH_MODULES`（复数），而 5.3.2 定义的、
   以及 5.3.3 和函数体里用的都是 `CONFIG_SUPPORT_TDTECH_MODULE`（单数）。
   照抄的话数组会走到 `[2]` 那个分支，而后面的循环要写 2 个元素，
   刚好不溢出但没有预留空间；再加 VID/PID 就会越界。统一成单数。

2. **5.3.5 的 `CONFIG_USB_FUNCTIONS_GENERIC` 不是真实的内核选项。**
   需要的是 `CONFIG_USB_SERIAL_GENERIC`。

3. **5.2.2 的 `CONFIG_USB_ SERIAL_WWAN` 中间多了个空格**，
   正确写法是 `CONFIG_USB_SERIAL_WWAN`。

4. **第 8 章 RNDIS 小节的正文写的是「MT5701G-CN 模块」**，而且配置项
   列的是 `CONFIG_USB_CONFIGFS_NCM`，明显是从 NCM 小节复制过来忘了改。
   RNDIS 主机侧要的是 `CONFIG_USB_NET_RNDIS_HOST`。

5. **第 6 章 ECM 小节让人「参考 9.3 CDC NCM 驱动编译配置项」**，
   应该是 9.2。

## 验证步骤

```sh
# 1. 模组是否枚举
lsusb -d 3466:3301

# 2. 驱动是否绑定、端口是否生成
dmesg | grep -iE 'option|usbserial|cdc_ether|cdc_ncm'
ls -l /dev/ttyUSB*

# 3. 确认哪个是 PCUI（一个窗口读，一个窗口写）
cat /dev/ttyUSB1 &
echo -e "ATI\r" > /dev/ttyUSB1

# 4. 网卡是否出来
ip link | grep -iE 'eth|usb|wwan'
```

拨号用 `AT^NDISDUP=1,1`，之后如果没拿到地址就跑一次 DHCP 客户端。
在 OpenWrt 上正常做法是把那个网卡配成 `proto dhcp` 的 interface，
交给 netifd 管，不要手动 `dhclient`。

## 报障时要带的信息

厂商文档 11.6 节列的那几样，一次收集齐：

```sh
dmesg > /tmp/dmesg.txt
ls -l /sys/bus/usb/drivers/ >> /tmp/usbinfo.txt
ls -l /sys/bus/usb/drivers/usbserial-generic/*/ >> /tmp/usbinfo.txt
cat /sys/bus/usb/drivers/usbserial-generic/*/bInterface* >> /tmp/usbinfo.txt
```
